# 쌍 기반 ΔpKi 예측 파이프라인 (`ac_pipeline.ipynb`)

한 곳만 다른 분자쌍 (A, B)를 입력받아 **Δ = p(B) − p(A)** 를 직접 예측한다.
3D CNN 인코더가 준비되기 전까지 인코더 자리는 GNN으로 채워두고, 그 앞뒤(입력 · 손실 · 평가 · 설명)를 먼저 완성하는 것이 목표다.

## 노트북 구성
| 섹션 | 내용 |
|---|---|
| 1–2 | MoleculeACE 30개 타깃 내려받기, 분자 단위 train/val/test split |
| 3–4 | "한 곳만 다른 쌍" 판정(MCS 기반)과 쌍 생성 |
| 4-1 | **학습 쌍 확대 (SQRL 방식)** — 유사 쌍 전부를 쓰는 설정 |
| 5–6 | 쌍 통계와 시각화, easy/hard 기준 |
| 7 | Baseline: ECFP + SVR (분자별 예측 후 차이) |
| 8–9 | 그래프 입력, GNN 쌍 모델, 가중 손실 학습 |
| 10 | 두 설정 비교, 학습 곡선, α 교환 곡선, \|Δ\| 구간별 MAE, 과분산 진단 |
| 11 | 결과 해석 |

## 모델 구조

![모델 구조](model_architecture.png)

- 두 분자를 **두 번 읽는다** — 한 번은 분자 전체, 한 번은 바뀐 부분만
- 읽은 결과와 편집 종류, 타깃을 이어 붙여 약효 차이를 바로 말한다
- 파란 칸(분자 전체를 읽는 부분)이 나중에 3D 입력으로 바뀔 자리다

## AC-aware 적용 지점
| 아이디어 | 구현 |
|---|---|
| ① 표현 | 바뀐 원자(MCS 밖)를 별도 인코더로, 편집 종류(replace/insert/delete/multi) one-hot |
| ② 손실 | `w = 1 + α·\|Δ\|`, 배치별 `Σw` 정규화. α는 validation cliff RMSE로 선택 |
| ③ 설명 | 원자별 기여도 → 편집 부위 비율 (미구현) |
| ④ 평가 | {train, easy, hard} × {cliff, non-cliff} RMSE + \|Δ\| 구간별 MAE |

## 실행
```bash
CUDA_VISIBLE_DEVICES=0 jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.timeout=-1 ac_pipeline.ipynb
```
- 환경: `aienv` (rdkit, torch, torch_geometric, scikit-learn)
- `data/`와 `runs/`는 커밋하지 않는다. 노트북이 데이터를 내려받고 쌍을 다시 만든다
- 쌍 생성은 MCS 계산 때문에 개발용 타깃 4개 기준 약 10분 걸린다. 결과는 `data/pairs/`에 캐시된다.
  판정 기준(`SIM_MIN`, `MAX_CHANGED` 등)을 바꾸면 `data/pairs/`를 지운다
- 학습은 α 5개 기준 약 55분(A100 1장). 가중치는 `runs/gnn_a{α}_{TAG}_seed{seed}.pt`에 저장된다.
  `TAG`에 hidden·dropout·weight decay·학습 쌍 확대 여부가 들어가므로, 설정을 바꾸면 캐시가 자동으로 갈린다
- 진행 상황은 `runs/train.log`에 남는다 (노트북 출력은 실행이 끝나야 저장되므로)

## 현재 상태 (2026-09-28, MoleculeACE 30개 타깃 전체)

### 고친 것 — 학습과 평가의 불균형

이전까지는 **학습과 평가가 서로 다른 종류의 쌍**을 쓰고 있었다.

| | 쓰던 쌍 | 구성 |
|---|---|---|
| 학습 | 유사 쌍 전부 349,565 | 한 군데만 다른 쌍 67,509 + **multi 282,056 (81%)** |
| 평가 | 한 군데만 다른 쌍 153,969 | **multi 0개** |

학습 쌍의 81%가 여러 군데 바뀐 쌍인데 평가에는 한 개도 없었다.
cliff 비율도 학습 27.7% vs 평가 22.1%로 어긋나 있었다.
**모델은 더 험한 세계에 맞춰 크기를 배우고 더 순한 세계에서 평가받은 셈**이고,
이것이 "예측을 실제보다 크게 말하는" 문제의 원인 중 하나였다.

그래서 **학습과 평가를 같은 종류의 쌍으로 맞춘 두 설정**을 따로 돌렸다.

| 설정 | 학습 쌍 | 평가 쌍(val+test) | 고른 α |
|---|---|---|---|
| **한 군데만 다른 쌍** | 67,509 | 86,460 | 4 |
| **유사 쌍 전부** | 349,565 | 451,868 | 1 |

각 설정마다 α 5가지 × 시드 3개 = 15회, 합쳐서 30회 학습했다.

### 1. 맞추니 과장이 줄었다

| test hard | 상관 | 기울기 (1에 가까울수록 좋음) |
|---|---|---|
| 한 군데만 다른 쌍 | 0.454 | 0.569 |
| **유사 쌍 전부** | **0.600** | **0.733** |

기울기가 1보다 작다는 건 **모델이 차이를 과장한다**는 뜻이다(0.57이면 "2"라고 말할 때 실제는 약 1.1).
학습과 평가의 성질을 맞춘 쪽이 **0.57 → 0.73으로 과장이 줄었다.**

SVR과의 격차도 좁아졌다 — test hard cliff(α=0 기준) **0.100 → 0.052로 절반.**

### 2. 학습 데이터가 많을수록 낫다

평가가 더 어려워졌는데도(평가 쌍 5.2배, cliff 비율 22.1% → 27.7%) 오차가 줄었다.

| test easy cliff | GNN α=0 |
|---|---|
| 한 군데만 다른 쌍 | 1.178 |
| 유사 쌍 전부 | **1.049** |

### 3. α 선택이 설정마다 갈린다

한 군데만 다른 쌍에서는 α=4, 유사 쌍 전부에서는 α=1이 뽑혔다.
**데이터가 적을수록 cliff 가중을 세게 걸어야** 하는 것으로 보인다.

### 4. 그래도 SVR에는 진다

| test split | | zero | SVR | GNN α=0 | GNN best |
|---|---|---|---|---|---|
| **한 군데만** | easy cliff | 1.720 | **0.928** | 1.178 | 1.138 |
| | easy non-cliff | 0.465 | **0.447** | 0.498 | 0.590 |
| | hard cliff | 1.715 | **1.256** | 1.356 | 1.342 |
| | hard non-cliff | **0.470** | 0.524 | 0.546 | 0.653 |
| **유사 쌍 전부** | easy cliff | 1.796 | **0.872** | 1.049 | 1.015 |
| | easy non-cliff | 0.490 | **0.459** | 0.522 | 0.576 |
| | hard cliff | 1.817 | **1.223** | 1.275 | 1.241 |
| | hard non-cliff | **0.491** | 0.554 | 0.608 | 0.662 |

- 두 설정 모두 모든 칸에서 SVR에 뒤진다. 가장 가까운 hard cliff에서도 1.241 vs 1.223
- **차이가 작은 쌍(non-cliff)에서는 "항상 0"보다도 못하다** — 어떤 α, 어떤 설정에서도
- 타깃별로는 30개 중 11개에서 GNN이 낫다

### 남은 문제

과장이 줄긴 했지만 여전하다(기울기 0.733 < 1).
예측 전체를 상수배로 줄이면 진짜 cliff까지 같이 나빠져 해결이 안 된다.
**쌍마다 확신도를 다르게 주는 장치**가 필요하다.

## 다음 단계
1. **시드 앙상블 · SVR과 섞기** — 재학습 없이 확인 가능. 두 모델이 상보적인지부터 본다
2. **ECFP 쌍 baseline** — 지문 차이만으로 Δ를 예측하는 단순 모델.
   "쌍으로 푸는 방식"과 "GNN 구현" 중 무엇이 문제인지 가른다
3. **조각 인코더 ablation** — 바뀐 부분을 따로 읽는 것(아이디어 ①)이 실제로 기여하는지 아직 안 재봤다
4. **cliff 판정 추가** — "이 쌍이 cliff인가"를 먼저 판단해 아닐 것 같으면 예측을 0 쪽으로 줄인다
5. **3D 입력** — 입체 구조와 전하 분포 반영
