# 쌍 기반 ΔpKi 예측 파이프라인 (`ac_pipeline.ipynb`)

한 곳만 다른 분자쌍 (A, B)를 입력받아 **Δ = p(B) − p(A)** 를 직접 예측한다.
3D CNN 인코더가 준비되기 전까지 인코더 자리는 GNN으로 채워두고, 그 앞뒤(입력 · 손실 · 평가 · 설명)를 먼저 완성하는 것이 목표다.

## 노트북 구성
| 섹션 | 내용 |
|---|---|
| 1–2 | MoleculeACE 30개 타깃 내려받기, 분자 단위 train/val/test split |
| 3–4 | "한 곳만 다른 쌍" 판정(ECFP4 Tanimoto ≥ 0.5 → MCS 밖 = 바뀐 부분)과 쌍 생성 |
| 4-1 | **유사 쌍 전부** — Tanimoto ≥ 0.5이면 전부 쓰는 두 번째 설정 (학습·평가 모두) |
| 5–6 | 쌍 통계와 시각화, easy/hard 기준 |
| 7 | 비교 대상: ECFP4 + SVR (분자별 예측 후 차이), "항상 0" |
| 8–9 | 그래프 입력, GNN 쌍 모델(구조·GINE 인코더·이어 붙이기·손실 그림), 가중 손실 학습, **분자별 GNN 비교군** |
| 10 | 모델 비교, **기준 분자로 개별 활성 추정**, 학습 곡선, α 교환 곡선, \|Δ\| 구간별 오차, 과장 진단 |
| 11 | 결과 정리 |

## 모델 구조

![모델 구조](model_architecture.png)

- 두 분자를 **두 번 읽는다** — 한 번은 분자 전체, 한 번은 바뀐 부분만
- 읽은 결과와 편집 종류, 타깃을 이어 붙여 약효 차이를 바로 말한다
- 파란 칸(분자 전체를 읽는 부분)이 나중에 3D 입력으로 바뀔 자리다

## AC-aware 적용 지점
| 아이디어 | 구현 |
|---|---|
| ① 표현 | 바뀐 원자(MCS 밖)를 별도 인코더로, 편집 종류(replace/insert/delete/multi) one-hot |
| ② 손실 | `w = 1 + α·\|Δ\|`, 배치별 `Σw` 정규화. α는 validation cliff RMSE로 선택 |
| ③ 설명 | 원자별 기여도 → 편집 부위 비율 (미구현) |
| ④ 평가 | {train, easy, hard} × {cliff, non-cliff} RMSE + \|Δ\| 구간별 MAE |

## 실행
```bash
CUDA_VISIBLE_DEVICES=0 jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.timeout=-1 ac_pipeline.ipynb
```
- 환경: `aienv` (rdkit, torch, torch_geometric, scikit-learn)
- `data/`와 `runs/`는 커밋하지 않는다. 노트북이 데이터를 내려받고 쌍을 다시 만든다
- 쌍 목록은 `data/pairs/`에 캐시된다 (MCS 계산이 오래 걸린다).
  판정 기준(`SIM_MIN`, `MAX_CHANGED` 등)을 바꾸면 `data/pairs/`를 지운다
- 가중치와 학습 기록은 `runs/`에 저장되고, 있으면 다시 학습하지 않는다
  - 쌍 모델: `gnn_a{α}_{TAG}_seed{seed}.pt` + `hist_...csv` (설정 2 × α 5 × 시드 3 = 30개)
  - 분자별 GNN: `gnnmol_{TAG}_ep1000_seed{seed}.pt` + `histmol_...csv` (시드 3개)
- **예측값도 `runs/preds_*.pkl`에 저장**된다. 있으면 예측을 건너뛰어, 그림·표만 고칠 때 전체 실행이 수 분이면 끝난다.
  파일 이름에 가중치 수정 시각이 들어가므로 다시 학습하면 자동으로 새로 예측한다
- 처음부터 실행하면 쌍 생성 + 학습 + 예측에 수 시간, 가중치만 있으면 약 1시간, 예측값까지 있으면 수 분
- 진행 상황은 `runs/train.log`에 남는다 (노트북 출력은 실행이 끝나야 저장되므로)

## 현재 상태 (2026-10-05, MoleculeACE 30개 타깃 전체)

### 평가 방식을 바꿨다 — 기준 분자가 있는 쌍만

이전에는 두 분자 모두 처음 보는 쌍(hard)도 Δ만으로 평가했다. 그러면 두 분자의 활성을 **똑같이 틀려도**
(실제 3, 0을 13, 10으로) Δ는 맞아서 정답 처리된다. 그래서

- **모든 쌍이 학습 분자(실측값을 아는 분자)를 하나 이상 포함**하도록 hard 쌍을 뺐다 (쌍 캐시에는 남겨 둠)
- **기준 분자 평가**를 추가했다: 평가 분자 B의 활성 = 학습 분자 A의 **실측값** + Δ̂(A→B), 기준이 여러 개면 평균.
  SQRL(Zadorozhny et al., 2024)도 같은 방식(가장 가까운 학습 분자를 기준)으로 추론한다
- 검증 쌍이 바뀌어 쌍 모델 30개를 다시 학습했다 (가중치 이름 끝 `_anchored`)

### Δ 예측 (평가 쌍, 시드 3개 평균)

| | | 항상 0 | **SVR** | GNN 분자별 | GNN 쌍 α=0 | GNN 쌍 best |
|---|---|---|---|---|---|---|
| 한 군데만 다른 쌍 | cliff | 1.720 | **0.928** | 1.397 | 1.134 | 1.091 (α=4) |
| | non-cliff | 0.465 | **0.447** | 0.563 | 0.486 | 0.565 |
| 유사 쌍 전부 | cliff | 1.796 | **0.872** | 1.356 | 1.060 | 0.988 (α=1) |
| | non-cliff | 0.490 | **0.459** | 0.591 | 0.521 | 0.586 |

GNN 분자별 = 같은 GINE 인코더로 분자 하나씩 예측한 뒤 빼는 모델 (SVR과 같은 방식)

### 개별 활성 추정 (기준 분자 평가, 한 군데만 다른 쌍)

| | 전체 분자 | cliff 분자 | 기준별 흩어짐 |
|---|---|---|---|
| SVR · 바로 | **0.625** | **0.741** | — |
| GNN 분자별 · 바로 | 0.763 | 0.851 | — |
| GNN 쌍 α=0 · 기준 분자 | 0.686 | 0.789 | 0.34 |

평가 분자의 76%(유사 쌍 전부는 93%)가 기준 분자를 가진다. 기준이 많을수록 쌍 GNN이 좋아져 11개 이상이면 SVR과 비슷하다.

### 알게 된 것
1. **쌍으로 넣는 것은 도움이 된다** — 분자별 GNN보다 모든 칸에서 낫다
2. **Δ만 맞추는 것이 아니다** — 실측 기준을 주면 개별 활성도 분자별 GNN보다 잘 맞힌다
3. **그래도 SVR에 진다** — 약점은 쌍 방식이 아니라 GNN 표현이다 (분자 하나 오차 GNN 0.82 vs SVR 0.69)
4. **GNN은 비슷한 분자를 덜 일관되게 본다** — 기준별 흩어짐 3배, 차이 과장(기울기 0.78) → non-cliff에서 "항상 0"보다 못함
5. **누수 점검** — 30개 타깃을 함께 학습해 평가 분자의 1/3이 다른 타깃의 학습 분자였다.
   처음 보는 분자에서 SVR과의 격차가 더 커서(cliff +0.15 → +0.25), GNN 숫자는 실제보다 조금 좋게 나온 것이다
6. **학습 데이터 5배의 효과는 작다** — 같은 평가 쌍에서 cliff 1.158 → 1.120 (hard 제거 전 기준)

## 다음 단계
1. **분류 후 예측** — 차이 구간(1 미만 / 1~2 / 2 이상)을 먼저 판단해 1 미만이면 0으로 답한다. cliff를 놓치지 않는 것이 관건
2. **GNN 표현 개선** — ECFP 함께 넣기, 사전학습 인코더, 시드 앙상블
3. **조각 인코더 효과 측정** — 바뀐 부분을 따로 읽는 것을 빼고 학습해 비교
4. **평가 쌍 범위 정리** — 평가를 한 군데만 다른 쌍으로 통일할지
5. **3D 입력** — 입체 구조와 전하 분포 반영
